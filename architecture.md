# Архитектура конвейера потоковых данных (MQTT -> Аналитика)

В данном документе описывается архитектура для получения, сохранения, обработки и анализа потоковых данных с нагрузкой ~100 500 сообщений в минуту, реализующая подход Data Lake и многоуровневого хранения (S3 -> PostgreSQL -> ClickHouse).

## Схема передачи данных (Data Flow)

```mermaid
flowchart TD
    subgraph Источник
        MQTT[Внешний MQTT Broker]
    end

    subgraph Сбор и Буферизация
        PB[Python Bridge\nMQTT -> Kafka]
        KAFKA[Apache Kafka\nТопик: raw_telemetry]
    end

    subgraph Data Lake (Сырые данные)
        SPARK_STR[Spark Streaming]
        S3[(S3 Compatible Storage\nMinIO)]
    end

    subgraph Долговременное хранение
        SPARK_BATCH[Spark Batch Job]
        PG[(PostgreSQL\nОперативное хранилище)]
    end

    subgraph Аналитическое хранилище
        CH_EXT[ClickHouse\nPostgreSQL Table Engine]
        DBT[dbt\nТрансформации]
        CH[(ClickHouse\nАналитические витрины)]
    end

    subgraph Оркестрация и Аналитика
        AIRFLOW[Apache Airflow]
        SUPERSET[Apache Superset]
    end

    %% Data flow
    MQTT -- "Подписка\n(JSON/Text)" --> PB
    PB -- "Запись сырого payload" --> KAFKA
    KAFKA -- "Чтение потока" --> SPARK_STR
    SPARK_STR -- "Быстрая запись (Parquet/JSON)" --> S3

    S3 -- "Чтение батчами" --> SPARK_BATCH
    SPARK_BATCH -- "JDBC Insert" --> PG

    PG -. "Чтение напрямую" .-> CH_EXT
    CH_EXT -- "dbt run" --> DBT
    DBT -- "Материализация витрин" --> CH

    CH -. "SQL запросы" .-> SUPERSET

    %% Orchestration
    AIRFLOW -. "Запуск по расписанию" .-> SPARK_BATCH
    AIRFLOW -. "Оркестрация dbt" .-> DBT
```

## Описание компонентов и слоев архитектуры

### 1. Источник данных: MQTT Broker
- Существующий внешний сервер, на который поступают данные (~100 500 сообщений в минуту, формат JSON/простые значения).

### 2. Сбор: Python Bridge (MQTT -> Kafka)
- **Функция:** Подписывается на топики MQTT, принимает входящие сообщения и отправляет их в Kafka.
- **Обоснование:** Легковесный скрипт на Python обеспечивает гибкость при приеме различных форматов и быструю пересылку в шину данных.

### 3. Буферизация: Apache Kafka
- **Функция:** Высокопроизводительный распределенный брокер сообщений.
- **Обоснование:** Обеспечивает отказоустойчивость. Гарантирует, что при пиковых нагрузках сообщения не будут потеряны, пока Spark их не прочитает.

### 4. Data Lake (Сырые данные): Spark Streaming + S3 (MinIO)
- **Функция:** Spark Streaming в реальном времени (или микро-батчами) читает топики Kafka и складывает сырые данные в объектное хранилище S3 (например, используя MinIO).
- **Обоснование:** Быстрая и дешевая запись сырых данных в форматах вроде Parquet или JSON. Выполняет роль Data Lake, где хранится абсолютно вся историческая неструктурированная информация.

### 5. Долговременное хранение: Spark Batch + PostgreSQL
- **Функция:** Apache Airflow по расписанию запускает Spark Batch Job, который читает новые файлы из S3, при необходимости проводит первичную очистку и записывает данные в PostgreSQL.
- **Обоснование:** PostgreSQL используется как надежное структурированное хранилище транзакционных данных (Оперативное хранилище). Использование Spark Batch позволяет не перегружать PostgreSQL частыми мелкими вставками, вставляя данные крупными пакетами.

### 6. Трансформация и Аналитика: dbt + ClickHouse
- **Функция:** ClickHouse подключается к PostgreSQL через встроенный `PostgreSQL Table Engine` (интеграция на уровне СУБД). Затем инструмент **dbt (Data Build Tool)** (оркестрируемый Airflow) выполняет SQL-модели, которые извлекают нужные для аналитики данные из PostgreSQL, трансформируют их и сохраняют в виде агрегированных витрин (MergeTree) в ClickHouse.
- **Обоснование:** Такой подход избавляет от необходимости писать кастомные скрипты перекачки PG -> CH. dbt позволяет версионировать трансформации, а ClickHouse обеспечивает молниеносные аналитические запросы.

### 7. Оркестрация: Apache Airflow
- **Функция:** Главный дирижер конвейера.
- Запускает `Spark Batch` задачи (S3 -> PG).
- Запускает `dbt run` (PG -> CH).
- Управляет будущими ML пайплайнами.

### 8. Визуализация: Apache Superset
- **Функция:** BI система, подключенная к готовым витринам в ClickHouse.
- **Обоснование:** Построение графиков и ML-аналитики на быстрых данных, подготовленных dbt.
